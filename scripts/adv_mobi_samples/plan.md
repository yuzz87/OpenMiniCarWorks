# 現在状況と次の計画

このメモは、現在の実機確認状況、PWM/ESC/サーボの考え方、同定実験、自律走行テストへ進むための流れをまとめたものです。

ここでは `ellipse_run` は対象外とし、現在動作確認できている `key_jog.py`、`demo.py`、`speed_observer.py`、`main.py` 周辺を前提にします。

## 現在できていること

`key_jog.py` により、Raspberry Pi から `pigpio.hardware_PWM()` を使って ESC とステアリングサーボを動かせる状態です。

現在の実機確認済みの前提:

| 項目                    |          値 |
| ----------------------- | ----------: |
| PWM周波数               |       70 Hz |
| ESC信号                 | BCM GPIO 12 |
| ステアリング信号        | BCM GPIO 13 |
| ESC中立 duty比          |     10.55 % |
| ステアリング中立 duty比 |     10.88 % |

70 Hz の場合、duty比[%]からパルス幅[us]への換算は次です。

```text
パルス幅[us] = duty比[%] * 142.857
```

そのため、現在の中立値は次のように換算できます。

```text
ESC中立: 10.55 % = 約 1507 us
ステアリング中立: 10.88 % = 約 1554 us
```

## PWM、duty比、パルス幅、速度の関係

PWM信号には、duty比[%]とパルス幅[us]という2つの見方があります。

```text
duty比[%] -> パルス幅[us] -> ESC/サーボへの指令 -> 実車の動き
```

| 項目     | 単位 | 意味                                  |
| -------- | ---- | ------------------------------------- |
| duty比   | %    | 1周期のうち信号がHighになっている割合 |
| パルス幅 | us   | 信号がHighになっている時間            |
| 速度     | m/s  | 車体が実際に進む速さ                  |
| ステア角 | rad  | 前輪が実際に切れている角度            |

重要なのは、パルス幅は速度そのものではないことです。パルス幅はESCへの入力指令であり、実際の速度[m/s]はバッテリー電圧、床面、車体重量、タイヤ、ESC設定などで変わります。

## ESCとは

ESC は `Electronic Speed Controller` の略で、モーターの回転を制御する部品です。

Raspberry Pi はモーターを直接動かしません。Raspberry Pi は ESC へPWM信号を送り、ESCが走行用バッテリーの電力を使ってモーター電流を制御します。

```text
Raspberry Pi GPIO
  -> ESC信号線
  -> ESC
  -> モーター電流を制御
  -> モーターが回る
```

GPIOや `3.3 V` ピンからモーターやサーボへ給電してはいけません。

## なぜPWMが必要か

RCサーボやRCカー用ESCは、PWMのパルス幅を指令として読むように作られています。

一般的には次のように扱います。

```text
1000 us 付近: 片側最大
1500 us 付近: 中立
2000 us 付近: 反対側最大
```

ただし、実機では完全に `1500 us` が中立とは限りません。今回の確認では、ESC中立は約 `1507 us`、ステアリング中立は約 `1554 us` です。

## key_jog.py の位置づけ

`key_jog.py` は、キーボード操作で duty比[%]を増減し、ESCとステアリングサーボを手動で動かす実機テスト用スクリプトです。

流れ:

```text
キーボード入力
  -> duty比[%]を変更
  -> pigpio.hardware_PWM()
  -> GPIO12 / GPIO13 へPWM出力
  -> ESC / ステアリングサーボが反応する
```

キー操作の意味:

| キー     | 動作                            |
| -------- | ------------------------------- |
| `w`      | 速度側 duty比を小さくする       |
| `s`      | 速度側 duty比を大きくする       |
| `a`      | ステアリング duty比を小さくする |
| `d`      | ステアリング duty比を大きくする |
| `n`      | ESCとステアリングを中立へ戻す   |
| `Enter`  | 終了                            |
| `Ctrl-C` | 中立へ戻して終了                |

`w` で前進する場合、「速度が小さくなる」のではなく、「ESCへ送るduty比が小さくなり、その実機ではその方向が前進側」という意味です。

## demo.py の位置づけ

`demo.py` は、自律走行テストではありません。決め打ちのパルス幅[us]を出す、PWM出力確認と簡単な走行デモです。

現在の主な設定:

| 項目                 |          値 |
| -------------------- | ----------: |
| ステアリング信号     | BCM GPIO 17 |
| ESC信号              | BCM GPIO 18 |
| 中立パルス幅         |     1500 us |
| スロットルずらし量   |       50 us |
| ステアリングずらし量 |      200 us |

注意点として、`demo.py` のGPIO17/18は、`key_jog.py` で確認したGPIO12/13とは異なります。実行前に実機配線と一致しているか確認が必要です。

`demo.py` から分かること:

```text
どのGPIOに、何usのPWMを出すか
```

`demo.py` だけでは分からないこと:

```text
1450 us が前進か後退か
1700 us が左か右か
1500 us で本当に停止/直進するか
実際の速度[m/s]
実際のステア角[rad]
```

これらは実機確認または同定実験で調べます。

## 実機実験後に分かること

実機で `demo.py` や `key_jog.py` を試すと、PWM指令が実車でどういう動きになるかが分かります。

確認できる例:

```text
1500 us でESCが停止するか
1500 us で前輪がまっすぐになるか
1450 us が前進か後退か
1700 us が左か右か
1300 us が反対方向に切れるか
accel = 50 が安全な低速か
steer = 200 が機械的に安全な切れ角か
```

ただし、正確な速度[m/s]やステアリング角[rad]は、別途測定が必要です。

## 同定実験で行うこと

同定実験の目的は、PWM指令と実車の物理量の対応表を作ることです。

最初に作る対応:

```text
ステアリングPWM[us] -> 実ステア角[rad]
ESC PWM[us] -> 実速度[m/s]
```

### ステアリング同定

車体を停止させた状態で、ステアリングパルス幅を変え、前輪角度を測ります。

記録する項目:

```text
steer_duty[%]
steer_us
steer_angle_deg
steer_angle_rad
```

角度変換:

```text
steer_angle[rad] = steer_angle[deg] * pi / 180
```

記録例:

```text
steer_us, steer_angle_deg, steer_angle_rad
1350, -20, -0.349
1554, 0, 0.000
1750, 19, 0.332
```

### 速度同定

一定のESCパルス幅で直進させ、決めた距離を進む時間から速度を計算します。

計算式:

```text
speed[m/s] = distance[m] / time[s]
```

記録する項目:

```text
throttle_duty[%]
throttle_us
distance_m
time_s
speed_mps
```

記録例:

```text
throttle_us, distance_m, time_s, speed_mps
1507, 0.0, -, 0.00
1540, 1.0, 5.2, 0.19
1560, 1.0, 3.7, 0.27
1580, 1.0, 2.8, 0.36
```

各点はできれば3回測り、平均値を使います。

## 変換関数

同定表ができたら、次の変換をコード化します。

```text
duty[%] -> us
steer_us -> steer_rad
throttle_us -> speed_mps
speed_mps -> throttle_us
```

最初は線形補間で十分です。

例:

```python
def interp(x, table):
    table = sorted(table)
    if x <= table[0][0]:
        return table[0][1]
    if x >= table[-1][0]:
        return table[-1][1]

    for (x0, y0), (x1, y1) in zip(table, table[1:]):
        if x0 <= x <= x1:
            ratio = (x - x0) / (x1 - x0)
            return y0 + ratio * (y1 - y0)
```

## 最初の自律走行テスト例

`demo.py` は自律走行ではありません。自律走行と呼ぶには、センサーで状態を読み、判断し、出力を変える必要があります。

最初におすすめの自律走行テストは、エンコーダを使った速度一定走行です。

構成:

```text
目標速度[m/s]
  -> エンコーダで現在速度[m/s]を測る
  -> 遅ければESC PWMを少し上げる
  -> 速ければESC PWMを少し下げる
  -> ステアリングは中立
```

最小テスト:

```text
目標速度: 0.1 m/s から 0.2 m/s
走行時間: 2 s から 3 s
ステアリング: 中立
終了時: ESCとステアリングを中立へ戻す
```

他の自律走行テスト例:

| テスト                  | 内容                                        |
| ----------------------- | ------------------------------------------- |
| エンコーダ速度一定走行  | 速度を測りながらESC PWMを調整する           |
| 色追従走行              | カメラで色の重心を検出し、中心へ寄せる      |
| 壁まで近づいて停止      | LiDARや距離センサーで前方距離を見て停止する |
| 時間指定 + センサー停止 | 一定時間前進し、異常や障害物で停止する      |
| ライントレース          | 床の線をカメラで検出して追従する            |

## MPPI制御を使いたい場合

MPPI制御を使うには、まずPWMを物理量へ変換できる必要があります。

必要な入力:

```text
現在状態:
x[m], y[m], theta[rad], v[m/s]

制御入力:
steer_rad[rad]
speed_mps[m/s] または acceleration[m/s^2]
```

そのため、今すぐ必要なのはMPPI本体ではなく、次の同定です。

```text
PWM[us] -> steer_rad[rad]
PWM[us] -> speed_mps[m/s]
```

現在の段階では、MPPIより先に、PWMと実車の動きの対応表を作ることが優先です。

## 安全確認

実機実験では必ず次を守ります。

- 最初は駆動輪を床から浮かせる。
- 低いスロットルから始める。
- すぐに物理的に電源を切れる状態にする。
- Raspberry Pi、ESC、サーボ電源のGNDを共通にする。
- モーターやサーボを Raspberry Pi のGPIOや `3.3 V` ピンから給電しない。
- 5 V出力のエンコーダ信号を Raspberry Pi GPIOへ直接入力しない。
- パルス幅、duty比、GPIO番号を変更したら、必ず低速・短時間で確認する。
- 終了時や例外時は、ESCとステアリングを中立へ戻す。

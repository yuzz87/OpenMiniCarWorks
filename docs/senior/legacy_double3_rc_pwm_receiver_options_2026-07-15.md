# legacy_double3_rc_pwm_receiver.py のオプション整理

対象ファイル:

- `OpenMiniCarWorks/UDP/legacy_double3_rc_pwm_receiver.py`

このメモは、これまでコマンドラインで変更していた主な項目を整理したものです。
実機安全を優先し、単位は SI 単位で統一します。
角度は `deg` と `rad` を明記します。

---

## 1. このスクリプトの役割

`legacy_double3_rc_pwm_receiver.py` は、UDP で受けた `float64 x 3` の旧形式コマンドを、RC カー用の PWM 指令へ変換するスクリプトです。

受信する値の意味:

- `raw_1`: 旧モータ指令 1
- `raw_2`: 旧モータ指令 2
- `raw_3`: 旧サーボ指令 `deg`

内部では主に以下を行います。

- `raw_1` と `raw_2` の平均から目標速度 `m/s` を作る
- `raw_3` から目標操舵角 `deg`, `rad` を作る
- それを ESC duty 比 `%` と steering duty 比 `%` に変換する
- 必要に応じて PWM を Raspberry Pi から実機へ出力する

---

## 2. よく使う変更項目

### 2.1 速度スケールを変える

オプション:

- `--speed-per-legacy-unit`

意味:

- 旧モータ指令 1 単位あたりを何 `m/s` とみなすかを決める係数です。
- `raw_1` と `raw_2` の平均値に掛けて `target_speed_mps` を作ります。

使う場面:

- 同じ Simulink / MPC 出力でも、実車が遅すぎる・速すぎるとき
- 旧指令値と実際の速度感の対応を変えたいとき

例:

```bash
--speed-per-legacy-unit 0.0090
```

注意:

- 値を大きくすると、同じ入力でも目標速度 `m/s` は大きくなります。
- 実機では急に大きくせず、段階的に確認します。

---

### 2.2 前進の最大速度を制限する

オプション:

- `--max-speed-mps`

意味:

- 目標速度の上限 `m/s` です。
- これを超える指令はこの値にクランプされます。

使う場面:

- 前進が速すぎるので抑えたいとき
- 床走行で安全側から試したいとき

例:

```bash
--max-speed-mps 0.38
```

または

```bash
--max-speed-mps 0.44
```

補足:

- 以前の整理では、受信側スクリプトの既存変換式ベースで
  `ESC duty = 10.100 %` を最大前進にしたい場合、
  `max_speed_mps ≈ 0.483 m/s` が目安でした。
- ただしこれは既存の速度変換式からの計算値であり、実測再同定値ではありません。

---

### 2.3 操舵の最大角を制限する

オプション:

- `--max-steer-rad`

意味:

- 目標操舵角の上限 `rad` です。
- `-max_steer_rad` から `+max_steer_rad` の範囲に制限されます。

使う場面:

- 曲がりすぎを防ぎたいとき
- 許容操舵角を実験条件に合わせたいとき

例:

```bash
--max-steer-rad 0.3141592654
```

これは約 `18 deg` です。

補足:

- 今回の会話では、命令としては `±23 deg` 程度の強さまであり得る、という整理がありました。
- ただし実際に許容する範囲は、安全値と実車の確認に基づいて決めます。

---

### 2.4 旧サーボ値から実際の操舵角への変換を変える

オプション:

- `--legacy-steer-a`
- `--legacy-steer-b`

意味:

- 旧サーボ指令 `raw_3` から実際の目標操舵角 `deg` を作る直線式の係数です。

式:

```text
target_steer_deg = legacy_steer_a * raw_3 + legacy_steer_b
```

使う場面:

- 操舵中立がずれるとき
- 左右の変換関係を再調整したいとき
- 旧 Simulink 側の出力定義と現在の実車側の対応を合わせたいとき

例:

```bash
--legacy-steer-b 70.9136
```

補足:

- `b` は中立位置のずれ補正として効きやすいです。
- `a` はサーボ値変化に対する操舵角の傾きに効きます。

---

### 2.5 ESC 中立 duty 比を変える

オプション:

- `--esc-neutral-duty`

意味:

- 停止時の ESC 中立 duty 比 `%` です。
- 目標速度がほぼ `0 m/s` のとき、この値を使います。

現在よく使っている値:

```bash
--esc-neutral-duty 10.300
```

使う場面:

- 停止のつもりでわずかに前進・後退してしまうとき
- 実車の個体差で中立がずれているとき

注意:

- ESC 中立ずれは安全に直結します。
- 小さな刻みで調整します。

---

### 2.6 ステアリング中立 duty 比を変える

オプション:

- `--steering-neutral-duty`

意味:

- 直進中立時の steering duty 比 `%` です。

現在よく使っている値:

```bash
--steering-neutral-duty 10.895
```

使う場面:

- 指令 `0 deg` なのに左右どちらかへ寄るとき
- サーボ中立が実車でずれているとき

注意:

- 空転時の結果と床走行時の結果が完全一致しない場合があります。
- 床走行ではタイヤ変形、摩擦、荷重、床面の影響も受けます。

---

## 3. 安全範囲の変更

### 3.1 ESC の安全範囲

オプション:

- `--esc-safe-min`
- `--esc-safe-max`

意味:

- ESC に出してよい duty 比 `%` の安全範囲です。

使う場面:

- 既知の安全範囲内だけに制限したいとき
- 予期しない値を reject したいとき

注意:

- むやみに範囲を広げないこと
- 特に前進側を強くしすぎる変更は危険です

---

### 3.2 ステアリングの安全範囲

オプション:

- `--steering-safe-min`
- `--steering-safe-max`

意味:

- ステアリングに出してよい duty 比 `%` の安全範囲です。

使う場面:

- サーボ端当てを避けたいとき
- 操舵の許容範囲を安全側に絞りたいとき

注意:

- サーボの機械端へ無理に当てる設定は避けます。

---

## 4. 制限付きでも出力する設定

オプション:

- `--allow-limited-output`
- `--confirm-accept-limited-output`

意味:

- 本来なら reject される一部の指令について、制限後の値で出力する設定です。

対象になりうる状態:

- `negative_speed`
- `clamped_speed`
- `clamped_steer`

使う場面:

- 実験中に、速度や操舵が上限に当たっても停止ではなく「安全側に丸めて出したい」とき

注意:

- 実機で使う場合は `--confirm-accept-limited-output` が必要です。
- どういう指令が丸められているか、ログを見ながら使います。

---

## 5. 実機出力の有効化

オプション:

- `--enable-hardware`
- `--confirm-wheels-lifted`
- `--confirm-power-cutoff`

意味:

- dry-run ではなく、Raspberry Pi から実際に PWM を出します。

注意:

- 通常確認では dry-run を優先します。
- 実機で使うときは、少なくとも以下を守ります。
  - 駆動輪を浮かせた確認を先に行う
  - 物理電源カットにすぐ触れられる状態にする
  - GPIO や電源配線を再確認する

---

## 6. タイムアウト・初期中立関連

### 6.1 ウォッチドッグ時間

オプション:

- `--watchdog-timeout`

意味:

- UDP が一定時間来なければ中立へ戻すまでの時間 `s` です。

使う場面:

- 通信断時に早めに止めたいとき
- 逆に、瞬間的な途切れで止まりすぎるなら見直したいとき

---

### 6.2 Param_init の中立判定

オプション:

- `--param-init-servo-deg`
- `--param-init-tol`

意味:

- 特定の初期パケットを「中立命令」とみなすための条件です。

使う場面:

- Simulink 側の初期化出力が既知で、それを明確に中立として扱いたいとき

---

## 7. これまで使っていた代表コマンド

### 7.1 dry-run 例

```bash
python3 -u legacy_double3_rc_pwm_receiver.py \
  --speed-per-legacy-unit 0.0090 \
  --max-speed-mps 0.38 \
  --legacy-steer-b 70.9136 \
  --esc-neutral-duty 10.300 \
  --steering-neutral-duty 10.895
```

用途:

- UDP を受けて、速度・操舵・duty 比の計算結果だけを確認する
- 実機を動かさずにログ確認する

---

### 7.2 実機出力ありの例

```bash
python3 -u legacy_double3_rc_pwm_receiver.py \
  --speed-per-legacy-unit 0.0090 \
  --max-speed-mps 0.44 \
  --legacy-steer-b 70.9136 \
  --esc-neutral-duty 10.300 \
  --steering-neutral-duty 10.895 \
  --allow-limited-output \
  --confirm-accept-limited-output \
  --enable-hardware \
  --confirm-wheels-lifted \
  --confirm-power-cutoff
```

用途:

- 制限付き出力を許しつつ、実際に PWM を出して走行確認する

注意:

- 床走行前に、まずは安全確認を十分に行うこと
- `pigpiod` が動作している必要があります

---

## 8. 最大前進を `10.100 %` にしたいときの考え方

今回の整理では、

- ESC 中立: `10.300 %`
- より小さい duty 比ほど前進が強くなる

という前提です。

そのため、

```text
最大前進 = ESC duty 10.100 %
```

としたい場合、`--max-speed-mps` を対応する速度上限に合わせます。

以前の計算メモでは、受信側スクリプトの既存変換式ベースで

```text
max_speed_mps ≈ 0.483 m/s
```

が目安でした。

ただし注意:

- これは既存式から逆算した値です
- 実測 2 点だけでは十分な再校正とは言えません
- 実際の床走行ではタイヤ、床面、バッテリ状態で変動します

したがって、実際には次のように進めるのが安全です。

1. まず低い `max-speed-mps` で dry-run / 空転確認
2. 次に床走行で短距離確認
3. ログと実測の進み方を見て微調整

---

## 9. いま特に意識したい点

現時点では、単純な PWM 出力不良よりも、以下の上流要因の確認が重要です。

1. OptiTrack / Motive のグラウンドプレーン設定
2. CS-200 による座標軸・原点設定
3. ゴール位置と参照軌道の解釈
4. Rigid Body の前方向定義
5. Simulink 内の座標変換

つまり、速度や操舵のコマンド調整だけでなく、
**どの座標系で「前」「左」「目標位置」を解釈しているか** の整合が非常に重要です。

---

## 10. 最低限の安全メモ

- `use_hardware` 相当の実機出力は、必要時だけ有効化する
- 駆動輪を浮かせた確認を先に行う
- 物理電源カットを手元に置く
- Raspberry Pi の GPIO は 3.3 V ロジックである
- サーボや ESC を GPIO から直接給電しない
- 停止・例外・Ctrl-C 時に中立へ戻る挙動を保つ
- duty 比や安全範囲は大きく一気に変えない

---

## 11. 次に見直しやすい項目

実験のたびに、まず次の 4 項目を記録すると整理しやすいです。

- `--speed-per-legacy-unit`
- `--max-speed-mps`
- `--legacy-steer-a`, `--legacy-steer-b`
- `--esc-neutral-duty`, `--steering-neutral-duty`

これに加えて、

- 実験時の目標位置
- 初期姿勢 `yaw`
- CS-200 / グラウンドプレーン設定状態
- 実際の走行結果

を残すと、後から比較しやすくなります。

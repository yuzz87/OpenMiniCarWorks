# 現在のMPC実機実験状況まとめ

作成日: 2026-07-15
更新日: 2026-07-15

## 目的

先輩のSimulink / Python MPC実験を現在のRCカーで再実行し、目標位置へ向けて前進・旋回・停止できるか確認する。

## 現在までにできたこと

### 1. 実験チェーン全体の動作確認

次の経路で実機まで動作確認できた。

```text
Motive
→ Simulink
→ Python MPC
→ Simulink
→ Raspberry Pi
→ 実車
```

### 2. 実車走行の確認

- 実車が前進した
- 十分な距離を進んだ
- 終了時に停止した
- `param_init_neutral` により中立復帰した
- `watchdog_neutral` も確認できた

したがって、通信、制御計算、Raspberry Pi変換、実車出力、停止復帰までは成立している。

### 3. 初期位置合わせの改善

現在の参照開始状態は次だった。

```text
[phi, x, y, psi] = [0, 0, 2, 0]
```

実際の `FIRST_RX` は次のようにほぼ一致した。

```text
(1.0, 0.0, 0.0311, 2.0111, 0.0)
```

したがって、最近の実験では初期位置の大ずれは主因ではない。

### 4. yaw基準の確認

車体を進ませたい方向へ向けたとき、Motive上で `yaw ≈ 0` を確認した。

したがって、少なくとも最近の確認では、yawゼロ方向の大きな取り違えは主因ではない可能性が高い。

### 左へ曲がる挙動についての整理

以前は「MPCが不自然に左へ寄る解を選んでいる可能性」を疑ったが、その後、左側にゴールが設定されていたことが分かった。

そのため、

```text
左側にゴール
→ 左操舵を選ぶ
```

こと自体は、MPCの異常とは限らない。

したがって、「左へ曲がること」単体を不具合とは断定しない。

## いま弱くなった疑い

## 現在の有力な問題点

### 最有力

#### 1. グラウンドプレーン / CS-200 / 座標軸設定のミス

現在もっとも有力なのは、OptiTrack / Motive側の座標系設定である。

特に疑っているのは次である。

```text
CS-200 の置き方
グラウンドプレーン設定
座標軸の向き
床面基準
x-y軸の意味
左・右の解釈
```

理由:

- 初期位置は数値上かなり合っている
- yawも0付近に見える
- それでも「自分が思うゴール方向」と実際の挙動の解釈にズレが残る

この場合、原点そのものではなく、座標軸の向きや基準面の取り方が微妙にずれている可能性が高い。

### 次点

#### 2. ゴール位置・参照軌道の解釈ミス

自分が想定しているゴールと、MPCが見ているゴールが一致していない可能性がある。

例:

- 左にゴールを置いていた
- 直進実験のつもりでも参照が左寄りだった
- `x0`, `y0`, `goal_dist` の意味の取り方がずれていた

この場合、MPCは正しく動いていても、人間の期待とズレる。

#### 3. Rigid Bodyの前方向定義

`yaw ≈ 0` でも、Rigid Bodyの前方向定義が車体の実際の前方と完全一致していない可能性は残る。

つまり、

```text
Motiveの yaw = 0
```

が

```text
車体の本当の前進方向
```

と少しずれている可能性がある。

#### 4. Simulink内の座標変換

Simulink内で次のような処理が入っている可能性がある。

- 軸の入れ替え
- 符号反転
- 別座標系での目標生成
- Pythonとのやり取り前後での変換

この場合、MPC内部の解釈と実車側の解釈が一致しない。

## いまは後回しでよいもの

### 5. MPCの重み・制約・モデル調整

以下は候補として残るが、優先順位は座標系確認より後である。

- `Q`, `R`, `Q_f`
- 操舵制約
- 速度上限
- ホイールベース
- 実車の操舵応答や速度応答との差

これらは、座標系とゴール設定の意味が正しいことを確認した後に調整すべき項目である。

## 現時点の結論

現在の実験系は、通信、制御計算、Raspberry Pi変換、実車走行、停止復帰まで成立している。

したがって、主因は実機接続不良ではない。

現在もっとも有力なのは、Motive / OptiTrack側の

```text
グラウンドプレーン
CS-200 の置き方
座標軸設定
```

に起因する座標系の解釈ずれである。

その次に、ゴール位置や参照軌道の意味の取り違え、Rigid Body前方向定義、Simulink内の座標変換を疑う。

## 要約

現在の問題は、MPCそのものが動かないことではなく、

```text
座標系とゴール設定の意味合わせ
```

がずれている可能性が高いことである。

特に、グランドの置き方を間違えた可能性は、現時点でかなり有力な問題候補である。

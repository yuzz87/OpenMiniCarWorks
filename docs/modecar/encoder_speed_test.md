# エンコーダ速度・距離計測記録

更新日: 2026-07-13

## 目的

新しい実機のA/B相エンコーダを使い、車輪の符号付きカウント、移動距離、速度を計測できるか確認する。

## 使用コード

リポジトリ内のサンプル:

```text
scripts/device_test/rccar_tests/test_encoder/encoder_speed_test.py
```

Raspberry Pi上でユーザーが実行したコピー:

```text
~/OpenMiniCarWorks/scripts/encoder/encoder_speed_test.py
```

このスクリプトはエンコーダ入力だけを読み、ESC、モーター、ステアリング、PWMへ出力しない。

## 仮設定

| 項目 | 値 | 状態 |
|---|---:|---|
| A相 | BCM GPIO 22 | リポジトリ既定値 |
| B相 | BCM GPIO 27 | リポジトリ既定値 |
| 1回転当たりカウント | 36 count/rev | 2026-07-13時点の暫定採用値 |
| タイヤ直径 | 0.066 m | 仮値 |
| 1カウント距離 | 約0.005759587 m | 上記仮値から計算 |
| 速度ゼロ判定 | 0.25 s | サンプル既定値 |
| 記録周期 | 約0.05 s、20 Hz | ログで確認 |

計算式:

```text
distance_per_count = pi * 0.066 m / 36
                   = 約0.005759587 m/count
```

## 初回の手回し試験

任意に正逆方向へ回した試験では、カウントの増減、正負速度、停止時の速度ゼロ化を確認した。

提供ログ内の概算最大速度:

```text
正方向: 約+0.143 m/s
逆方向: 約-0.148 m/s
```

これは手回し時の車輪周速度であり、校正前の仮値である。

## タイヤ1回転試験

タイヤを一方向へ1回転させた結果:

```text
最終カウント = -34 count
表示距離     = -0.19583 m
```

仮設定36 count/revとの関係:

```text
34 / 36 = 約0.9444
pi * 0.066 m * 34 / 36 = 約0.19583 m
```

### 判定

- カウントは`0`から`-34`まで単調に減少した。
- A相入力とB相方向判定は動作している。
- 回転方向は現在のソフトウェア規約では負方向である。
- ユーザー確認により、この負方向が実車前進方向である。
- 1回だけでは実効値を34 count/revと確定しない。

リポジトリ上の仮値36 count/revに対し2カウント少ない。候補原因:

- タイヤの開始・終了目印が完全には一致していない。
- センサー位置や遮光板の調整により一部パルスを検出していない。
- エンコーダ歯数と、A相立ち上がりで得られる実カウント数が異なる。
- 配線・信号品質による取りこぼし。

手回し速度は低いため、ソフトウェア処理速度だけが原因で2パルス落ちた可能性は高くないが、複数回転試験で確認する。

## 36 count/revを暫定採用する判断

1回転試験は手回しの感覚で開始・終了を決めており、目印を厳密に一致させた試験ではなかった。ユーザー判断により、現段階ではリポジトリ既定値の`36 count/rev`を暫定採用する。

```text
counts_per_wheel_rev = 36
```

`34 count/rev`への変更は行わない。速度・距離の最終校正値として確定したわけではない。ユーザー方針により、既知距離手押し試験とMotive比較は一旦保留し、36 count/revのままPowered runへ進む。

## 将来必要になった場合の複数回転校正

タイヤと固定部へ目印を付け、同じ方向へ途中で戻さず、正確に5回転または10回転させる。

期待値:

| 仮定 | 5回転 | 10回転 |
|---|---:|---:|
| 36 count/rev | 180 count | 360 count |
| 34 count/rev | 170 count | 340 count |

判定例:

- 5回転で毎回約170 countなら、実効値34 count/revの可能性が高い。
- 5回転で約178〜180 countなら、1回転試験の目印ずれまたは一時的な取りこぼしの可能性がある。
- 試験ごとの値が大きく変動する場合は、センサー間隔、遮光板、信号電圧、ノイズを確認する。

校正用コマンド例は、実機配線が3.3 V互換かつ共通GNDであることを確認した場合だけ使用する。

```bash
python3 encoder_speed_test.py \
  --use-hardware \
  --confirm-3v3-compatible \
  --confirm-common-ground \
  --duration-s 30 \
  --zero-timeout-s 0.6
```

`--zero-timeout-s 0.6`は低速手回し時の表示を見やすくするためであり、最終的な速度制御設定ではない。

## 方向の確認

実車前進方向へ手回ししたとき、カウントは負になった。

```text
実車前進 -> 生カウントは負
```

速度・距離ログでは前進を正として扱うため、Powered run用コードでは方向をソフトウェアで反転する。

```text
invert_direction = True
```

既存の配線は変更せず、A/B相の意味と生ログを記録した上で符号変換する。

## Powered runで確認した値

2026-07-13、ユーザー実測により次を確認した。

```text
ESC中立                = 10.3 %
無負荷で車輪が回る値   = 10.2 %付近
接地時に車体が動く値   = 10.1 %付近
ステアリング中立       = 10.895 %
前進方向               = Duty比を下げる方向
```

`10.1 %`は`10.2 %`より強い前進出力である。Powered runコードの前進上限を`10.1 %`へ変更するが、床走行許可とは扱わず、最初は駆動輪リフト状態でログと中立復帰を再確認する。

## キーボードJog＋エンコーダのリフト試験結果

`r`によるarmと`w`による`forward_step`をCSVで確認した。キー入力処理は正常である。

ログ上の無負荷回転開始:

```text
10.28 %: count変化なし
10.26 %: count変化なし
10.24 %: count変化開始
```

提供ログ内の速度絶対値の概算:

```text
10.24 %: 約0.17〜0.62 m/s
10.22 %: 約0.63〜0.83 m/s
10.20 %: 約0.85〜1.04 m/s
10.18 %: 約1.04〜1.09 m/s
```

これらは駆動輪リフト時の無負荷車輪周速度であり、床に対する車体速度ではない。

10秒の時間上限により`10.18 %`で終了し、今回のログでは`10.10 %`へ到達していない。

終了行:

```text
neutral_exit:time_limit
ESC duty = 10.300 %
steering duty = 10.895 %
encoder speed = 0.0 m/s
```

時間上限後の中立復帰を確認した。中立出力後も車輪慣性でカウントが増え、最終サンプルは約1秒後に保存されている。

### Powered runを基準にエンコーダ符号を修正

ユーザー確認により、Powered run時の車輪は物理的な前進方向へ回っていた。

`invert_direction = True`ではログが主に負になったため、統合Powered runコードでは符号反転を無効にする。

```text
変更前: invert_direction = True  -> 物理前進が負ログ
変更後: invert_direction = False -> 物理前進を正ログにする予定
```

手回し時の方向認識とPowered runの物理方向が一致していなかった可能性がある。実車の駆動方向を運用基準とする。

高速域で少数の逆符号カウントが混ざったため、修正後に低出力の駆動輪リフト試験を1回行い、countとspeedが主に正であることを確認する。

### 速度設定の維持

ユーザー判断により、Powered runの速度設定は変更しない。

```text
ESC neutral       = 10.3 %
forward duty limit = 10.1 %
forward duty step  = 0.02 %
```

一時的に提案した`--forward-duty-limit 10.24`は符号だけを低出力で確認するための任意オーバーライドであり、コード既定値は`10.1 %`のままである。今回の修正対象はエンコーダ計測方法だけとする。

## 未更新コードでの10.1 %までのリフト試験

ユーザー確認により、試験時の車輪は物理的に前進していた。Raspberry Pi上のファイルは符号修正前の版であり、ログは主に負値だった。

```text
10.28 %: count変化なし
10.26 %: count変化なし
10.24 %: 回転開始
10.10 %: 無負荷速度絶対値が概ね1.5〜1.8 m/s
```

時間上限後は次になった。

```text
neutral_exit:time_limit
ESC = 10.3 %
steering = 10.895 %
speed = 0.0 m/s
```

駆動・キー操作・中立復帰は正常である。

### 高速域のB相方向判定問題

`10.1 %`付近では、車輪が物理的に前進し続けているのに、速度ログが約`+1.7 m/s`と`-1.7 m/s`で頻繁に反転し、ゼロも混ざった。countも増減を繰り返した。

A相立ち上がりをpigpioデーモンが検出した後、Pythonコールバック内の`pi.read(B)`で現在のB相を読む方式では、高速回転時にB相が既に次の状態へ変化し、方向を誤判定する可能性がある。

前進専用Jogでは逆転指令を出さないため、次の方式へ変更した。

```text
A相立ち上がりを常に+1 countとして記録
B相による方向判定は前進専用Jogでは使用しない
fixed_direction = +1
```

汎用の正逆転オドメータではなく、今回の前進専用速度計測に限定した対策である。速度設定、ESC Duty、ステアリングDutyは変更していない。

## 安全

- Raspberry Pi GPIOへ5 V出力を直接接続しない。
- Raspberry Pi、エンコーダ、ESC信号、サーボ電源/BECのGNDを共通にする。
- エンコーダの端子順はデータシートまたは測定結果で確認する。
- モーターを使う前に、手回し・手押しでカウント数、符号、距離を校正する。
- Powered runは駆動輪を床から浮かせ、低出力、物理電源カットへ手が届く状態で行う。

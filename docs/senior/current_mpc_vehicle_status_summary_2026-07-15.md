# 現在のMPC実機実験状況まとめ

作成日: 2026-07-15

## 目的

先輩のSimulink / Python MPC実験を現在のRCカーで再実行し、目標位置へ向けて前進・旋回・停止できるか確認する。

## 現在までにできたこと

### 1. 実験チェーン全体の動作確認

次の経路で実機まで動作確認できた。

```text
Motive
→ Simulink
→ Python MPC
→ Simulink
→ Raspberry Pi
→ 実車
```

### 2. 実車走行の確認

- 実車が前進した
- 十分な距離を進んだ
- 終了時に停止した
- `param_init_neutral` により中立復帰した
- `watchdog_neutral` も確認できた

### 3. 初期位置合わせの改善

現在の参照開始状態は次だった。

```text
[phi, x, y, psi] = [0, 0, 2, 0]
```

実際の `FIRST_RX` は次のようにほぼ一致した。

```text
(1.0, 0.0, 0.0311, 2.0111, 0.0)
```

したがって、最近の実験では初期位置の大ずれは主因ではない。

### 4. yaw基準の確認

車体を進ませたい方向へ向けたとき、Motive上で `yaw ≈ 0` を確認した。

そのため、少なくとも現在の確認では、yawゼロ方向の大きな取り違えは主因ではない。

## 走行で観察された挙動

### 初期の実験

- 蛇行した
- 操舵と速度が不安定だった

### その後の実験

- 蛇行は減少した
- 左へ曲がっていく挙動が残った

### 解釈

現在の問題は、実機I/Oが動かないことではなく、MPCがゴールへ直線的に向かわず、左へ寄る解を選んでいることである。

## 旧形式変換について分かったこと

初期の `ok` パケットでは次が確認できた。

```text
raw3 = 85.997574582
target_steer_deg = 0.0 deg
```

したがって、SimulinkからRaspberry Piへの旧形式変換が最初から壊れているわけではない。

一方、走行途中では左向きの操舵指令へ移っていった。

## 現在の理解

以下は、少なくとも最近の実験では主因ではない可能性が高い。

- 初期位置の大きなずれ
- yawゼロ方向の大きな取り違え
- 旧形式変換の初期破綻
- 実車がまったく反応しないこと

一方、現在も残っている本質的な問題は次である。

```text
MPCがゴールへ直線的に向かう解ではなく、左へ曲がる解を選んでいる
```

## 現時点の結論

現在の実験系は、通信、制御計算、Raspberry Pi変換、実車走行、停止復帰まで成立している。

未解決なのは、現在の設定ではMPCが期待する直進的な到達行動ではなく、左へ曲がる行動を選んでいる点である。

したがって、次に確認すべき焦点は、実機接続ではなく、MPC内部の状態解釈、制約、重み、参照に対する解の選ばれ方である。
